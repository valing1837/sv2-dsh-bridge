# 音高对照 —— 用原唱人声判断"哪里唱得不对劲"

> 起因(2026-10-11):用户给人声干声,说"调一下工程的音高曲线,有些唱起来很不对劲"。
> 于是做了一条**可量化的**路子:从原唱提基频 → 和工程逐音对照 → 才知道"不对劲"到底在哪几个音上。
> 过程中我自己错了三次(采样率、半频、scoop),三次都靠**核数据**抓回来 —— 这份文档主要记那三次。
> 工具:`tools/track-f0.py`、`tools/compare-pitch.py`(各自 `--selftest`)。

---

## 0. 一句话

**音高曲线是最后手段,不是第一手段。**
判据不是"我觉得怪",而是"**原唱在这个音上是多少赫兹**" —— 先量出来,再决定动不动手。
实测一首正常转录的歌:**83% 的音本来就在 ±30 音分内**(563/586 在 ±80 音分内) ⇒
"不对劲"通常是**个别音**,而不是整首跑调。

## 1. 两步

```powershell
py = C:\Users\huang\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe

# ① 从人声干声提基频(10ms 步长,65~700Hz)
& $py tools\track-f0.py 人声.wav vocal-f0.csv

# ② 逐音对照:--notes 给桥 get_layout 的 JSON(整份或只给 layout 数组)
& $py tools\compare-pitch.py --notes layout.json --f0 vocal-f0.csv --bpm 90 --out report.csv
```

`layout.json` 的取法:让助手调 `get_layout {scope:"group"}`,把返回**原样存成文件**
(工具认 `onsetQuarter` / `durationQuarter` / `pitch`;不自己去猜别的形状)。

输出:`最佳偏移` + `偏差中位` + `±30 音分内的比例` + **超过阈值(默认 40 音分)的音符清单**。
那张清单才是"哪里不对劲"的答案。

## 2. 三条实测结论(每条都在 `--selftest` 里有断言)

### 2.1 先求时间轴偏移 —— 错了会**伪装成八度错误**

WAV 的 0 秒未必是工程的 0 拍。实测《風に吹かれて》偏移 **−0.02s** 时"±80 音分内"命中最多。

⚠️ **这条坑还会伪装**:时间轴偏了之后,逐音对照是在**错误的时刻**取样 ——
于是读到的是**别的音**的音高,表现为"某个音低了整整一个八度(−1198 音分)"。
我一度判定"转录把音写高了八度",还据此改了用户的音符;后来用频谱复核才发现
**原唱在那个音上就是 466Hz**(该处能量 3.16,半频处只有 0.0499)——
真凶是采样率算错导致的时间线压缩。**两个音符已改回,并留下这条教训。**

> 判据:**看到"差一个八度",先怀疑时间轴,再怀疑基频提取。**

### 2.2 scoop 不是音准 —— 目标音高只看"滑入完成之后"

人声大量音符是**从低处 scoop 上来**的(实测第一个音:头 −123 音分 → 稳定段 −3 音分)。
拿"中段中位数"当音高,会把一整批本来唱准的音判成"低了 100~180 音分"
(实测:一堆 p=63 的音被量成 61.2~62.3),照这个去写曲线就是**把整首往下拽** ——
这正是用户听完说"音高太怪"的直接原因之一。

⇒ **目标音高取稳定段(45%~80%),滑入交给音头**(音头点可以照实写着 −120 音分)。

⚠️ 但要说实话:**短音上这条也只是缓解,不是解决** ——
0.2 秒的音里滑入可能占掉一半,稳定段仍然被污染(`--selftest` 里那条断言就是
"稳定段比中段**更准**",不是"稳定段一定准")。

### 2.3 稀疏控制点 + 三次插值 = 振铃

把原唱的**连续**曲线采样成"每音 3 个点"再交给 `set_automation`,得到的是**失真**:
三次插值会在控制点之间自己编动作、并且过冲。
用户听完的评价是"**音高太怪**",曲线随即被整条压平。

⚠️ 讽刺的是:这个"窄尖峰 + 振铃"的形状,正是我在用户那份 SV1 工程里一眼认出的
**转换伪影**(见 §4)—— 我认出了它,却又亲手做出了一个同形态的东西。

---

## 3. 结论:音高曲线到底怎么用

1. **默认不写**。转录本身通常够准(83% 在 ±30 音分内),平线听起来是自然的。
2. 真要写,就**极稀疏、逐句手工**:一次一个音或一句,**写完立刻让人听**。
3. **绝不要**"把原唱采样成点阵再灌进去"(§2.3)。
4. 一个前提:**自动化曲线不在快照覆盖范围内** ⇒ `sv_undo` 救不了它。
   `Automation` 只暴露 `add`/`get`,**没有删除点的 API** ⇒ 只能靠用户 `Ctrl+Z`,
   或者用"同一位置写 0"覆盖。⇒ **"别写"比"写了再撤"重要。**
5. ⚠️ `get_computed {kind:"pitch"}` 读到的是**音符算出来的**音高,**不反映自动化曲线**
   (实测:写入曲线前后几乎不变)⇒ **没法用它验证音高曲线的效果,只能靠耳朵**。

## 4. SV1 → SV2 的转换会毁掉手画音高(用户 2026-10-11 确认"sv1转sv2就是会这样")

拿用户一份 SV1 参赛工程(293 音符)对照,实测:

| SV1 里的东西 | 到 SV2 之后 |
| --- | --- |
| `mouthOpening` 曲线 | **没有**(`getParameter` 里不存在) |
| 音符的 `takes` / `seedDuration` / `seedPitch` / `seedTimbre` | **没有** |
| `accent` | 改名 `rapAccent` |
| `evenSyllableDuration` | 保留 |
| `dF0VbrMod` | **保留**(逐音符颤音调制) |
| `tF0Left` / `dF0Left` / `tF0Right` / `dF0Right` 等**逐音符音高过渡参数** | **折进了音高曲线** |
| `pitchDelta` 曲线 | 保留,但**形状已坏**(见下) |

⚠️ **怎么认出坏掉的 pitchDelta**:SV1 那份的曲线在 SV2 里表现为**一串又窄又高的尖峰** ——
实测 36 拍处:0.25 秒内冲到 **+743 音分**再立刻回零,峰值后面紧跟**插值振铃**
(−2.5 音分那种小尾巴)。人手画的音高是**平滑微调(±几音分到几十音分)**,不长这样。

⇒ 判据:**窄尖峰 + 振铃 = 转换伪影**,不是用户的曲线,**不要去"修"它**,更别照它判断音准。
⇒ 想听原味只能回 SV1 打开;在 SV2 里能做的只有把这条曲线压平(见 §3.4 的限制)。

## 5. 这一轮到底做了什么(留档)

* 用户给的干声:92.3MB / 44100Hz / 立体声 / **IEEE float WAV**(format tag 3)——
  标准库 `wave` 不认,所以 `track-f0.py` 自己解析 RIFF 块(**16/24/32 位 PCM + 32/64 位 float**)。
* 44.1k → 分析速率抽 3 取 1 = **14700Hz**(不是 16000)—— 这条差点毁掉整轮分析(§2.1)。
* 逐音对照结果:586 个音全部测到,偏差中位 **−9.2 音分**,83% 在 ±30 音分内,
  \>50 音分 **37 个**、>80 **13 个**、>100 **8 个**。
* 我先按"每音三个点"照原唱画了 1896 个点的音高曲线 ⇒ 用户听完"**音高太怪**" ⇒
  **整条压平置 0**(同一位置覆盖,回读确认全 0),音符层回到转录原样。
* 期间的两个音符改动(70→58 / 70→67)**已改回 70** —— 那是被 §2.1 那个错误读数误导的。

**最终状态**:音高 = 平线(等于没动)。其余六层(气声 / 张力 / toneShift / voicing /
gender / 颤音)与全曲响度曲线保留 —— 那些是逐音核对过的,用户听过认可。
