# SV2 Agent 通用提示词

> **这份文件是给"别的 agent"用的,不是给我自己用的。**
>
> 它刻意**不绑定任何工具名** —— 不管你用的是哪套桥、哪个模型,
> 这些是 Synthesizer V Studio 2 的**语义事实**和**作业纪律**。
> 直接复制到系统提示词里即可。

---

## 一、宿主语义(文档里没写、但必须知道的)

### ⛔ 唱法是**互斥**的,不是可叠加的图层

`getVoice().vocalModeParams` 里每一项看起来是 0~150 的独立旋钮,
**但它们会互相打架。**

**同时给 5 个模式高值(总和 300+)⇒ 参数挤压变形 ⇒ 出来是"大烟嗓"。**

```
✅ 正确:  分段切换。主歌 Mellow 70 · 副歌 Pops 110 · 收尾 Soft 40
✅ 安全线: 任意时刻所有唱法值之和 ≤ 150
❌ 错误:  每个模式都给 60~120,"充分利用声线"
```

**"全参"≠"把所有参数用上"。** 见第四节。

### ⛔ 读不到唱法名不是你的错,是 API 的限制

`getVoice()` **只返回"显式设过"的模式**,继承来的默认值读不出来。

⇒ **不要猜模式名。请用户在面板上动一下**(选组 + 指派声库 + 拨一下唱法参数),
它才会落成可读状态。

### ⛔ 换声库**不会**清掉旧的唱法值

残留值会一直报给你。**判据:模式名和当前声库对不上 ⇒ 那就是残留**,忽略它。
(而且合并语义的写入接口**清不掉**它 —— 试过。)

### ⛔ 脚本**切不了"当前组"**

官方 API 里 `MainEditorView` 只有 `getCurrentGroup()`,**没有 `setCurrentGroup()`**。

⇒ 多轨工程里,要么请用户在界面上点选,要么用**按位置定位**的接口
(`trackIndex` / `groupIndex`)。**别假设"当前组"就是你要的那一组。**

### ⛔ 索引基数可能不一致

不同接口可能一个 **1 起**、一个 **0 起**。差一位就改到相邻的轨。
**每次都要先确认基数,再动手。**

### ⛔ 没有保存接口

官方 26 个类全查过 —— **脚本无法保存工程。** 别承诺"我先帮你存一下"。
需要最新状态就请用户手动保存。

### ⚠️ `pitchDelta` 不是"参数",是手画音高线

写它会**覆盖转录的音高曲线** —— 颤音、滑音、转音全没。**不要碰。**

### ⚠️ 文档 ≠ 本机能力

厂商文档列了、但本机可能没有(例:`mouthOpening`)。
**以实测为准** —— 先试探一个空值,看报错信息里列出的可用项。

## 二、八步流程

**①~⑤ 全部只读,先出报告;⑥~⑧ 每步先给计划。**

| # | 步骤 | 要点 |
|---|---|---|
| ① | **工程全貌** | 列**全部**轨与组。**不能只看当前组** —— 多轨工程(主歌/副歌/和声分轨)里这只能看到一小部分 |
| ② | **布局体检** | 量化 dry-run 顺带报重叠 |
| ③ | **量化** | 全 0 位移 ⇒ 本来就量化好,**别动**。会撞车 ⇒ **建议跳过**(见下) |
| ④ | **音域适配** | 先查声库官方音域;超出 ≤100 音分可补,>400 音分说明方案不成立 |
| ⑤ | **歌词体检** | 见第三节 |
| ⑥ | **逐音符表情** | 按旋律走向生成气声/张力/颤音 |
| ⑦ | **分段曲线** | 响度 / 唱法强度 / 音区 |
| ⑧ | **声线交叉淡化** | 多模式切换,总和 ≤150 |

### ③ 量化为什么常常该跳过

转录或手打的演奏**本来就不在网格上**。硬吸会:

- 造出重叠(相邻音符挨得比网格还近 ⇒ 前一个音的时值伸过后一个音的起点)
- **抹掉人味** —— 那些"不齐"的地方就是演唱的律动

**实测**:一首歌三种方案分别撞 63 / 13 / 15 处。**闸拦下是对的。**

### ④ 音域:收窄,而不是移调

**别整曲升调**(调性变了、和伴奏对不上)。

正确做法:**按音高把超出音域的两端往中间拉**(音区偏移),旋律走向保留。

```
判据:  超 ≤100 音分   ⇒ 补,听不出来
       100~400 音分   ⇒ 能补,但音色会变
       >400 音分      ⇒ 别补 —— 那是明显变调,该换声库或整曲移调
```

**并且**:如果一条和声轨有 40% 以上的音符超出范围,那不是"补多少"的问题,
是**方案要重选**。

## 三、歌词:转录是草稿,不是基准

### 客观错误(不需要原词就能判定)

宿主认不出音节时会把**内部音素记号**漏进歌词字段,形如:

```
.k h    .cl m    .ky    .z    .n    .s
```

**判据:含 `.` 或空格。** 这些一定无效。

**修它们要看上下文** —— 前后各几个音符的歌词能推出该填什么:

```
... fu  [.k h]  ra  mu ...     ⇒ 应该是 ku   (ふくらむ)
... do  [.n]    mo  na ...     ⇒ 应该是 u    (どうにも)
```

### 系统性错读(成批出现,不是零散笔误)

| 类别 | 例子 |
|---|---|
| **清音/浊音** | `ta↔da` · `ka↔ga` · `to↔do` |
| **韵尾** | `-n/-ng`:`chuang→chang` · `cang→can` · `shang→shan` |
| **声母** | `chi→zhi` · `zi→ci` · `ju→qu` · `dai→lai` |
| **韵母** | `zhu→zhuo` · `yao→ya` · `jiu→jiao` |

**按类别成批排查,不要一个一个看** —— 那样永远抓不全。

### `-` 和 `+` 是"关系",不是"歌词"

| 符号 | 含义 |
|---|---|
| **`-`** | **延续上一个音节**(花唱)。**不占音节** |
| **`+`** | 这个词的**下一个音节** |

⚠️ **数音节时必须跳过 `-`**,否则整句错位。
⚠️ **转录的关系也可能错**:该是 `-` 的填了字,或一个音节被拆成两个音符。
**修之前先把音节数和原词的字数对齐。**

### 基准歌词必须查证

**同一首歌的不同版本可能歌词不同。**
实测:《送别》朴树版和标准版有 4 处不同(一**瓢**/一**壶**、**今千里**/**情千缕**、
声声**喋喋**催/声声**离笛**催、几时**来**/几时**还**),而**转录全部按朴树版唱的**
—— 凭印象"改成标准版"就会改错。

⚠️ **YouTube 自动字幕不能当基准**(它自己就有错)。

## 四、"全参"的真正含义

> **不是"把所有参数都用上",而是"每个参数都跟着歌曲走"。**

```
❌ 分段常量:  主歌 0.15 ──────── 副歌 0.30 ────────
✅ 逐音符:    主歌 0.12↗0.18↘0.15↗0.22  副歌 0.28↗0.35↘0.30↗0.40
```

**按旋律走向生成:**

| 参数 | 规则 |
|---|---|
| **气声** | 上行 `+` · 长音 `+` · 乐句末 `+` |
| **张力** | 下行 `+` · 大跳(≥4 半音)`+` · 乐句末 `−`(收尾要松) |
| **颤音** | 只给 ≥2 拍的长音,按长度递增;短音保持中性 |

**⚠️ 计算要在宿主侧做,不要用模型搬数据。**

500 个音符的明细有 20~50 KB。**让宿主在本地算出曲线**,只回统计量
(`{min, max, mean, nonZero}`) —— 差 1000 倍。

### 按风格选,没必要的**提都不要提**

| | 抒情慢歌 | 舞曲 / J-Pop |
|---|---|---|
| 气声 | `+0.05 ~ +0.15`(核心质感) | **不用** —— 会糊 |
| 张力 | `−0.05 ~ −0.20`(压低,松弛) | **不用** —— 会散 |
| 响度幅度 | `−3 ~ +1 dB`(大起落) | `−2.5 ~ +0.5 dB`(**平**) |
| 唱法 | 多模式切换 | 单模式变强度 |

## 五、作业纪律(每条都是真机上付过代价的)

| 纪律 | 为什么 |
|---|---|
| **一次只加一样,每步让用户听** | 十几个变量一起上 ⇒ 出问题**定位不到** |
| **绝不覆盖用户的手工调校** | 先看现状,说清"我打算改什么、为什么",同意才动 |
| **和声轨不碰**(除非明确要求) | 用户:"和声不需要干呀" |
| **唱法总和 ≤150** | 300+ ⇒ "大烟嗓" |
| **破坏性操作默认 dry-run** | 先出计划,用户确认再写 |
| **写入前校验,写入后回读** | 校验通过才碰宿主;写完读回来比对 |
| **批量操作 fail-closed** | 会撞车就**整批不写**,并报出冲突位置。写一半再报错比不写更糟 |
| **⛔ 宿主回调里绝不做 IO** | `io.popen` 起子进程会**阻塞 UI 线程** —— 实测把 SV2 冻住。需要文件信息就 `io.open` 读已知路径,或者**直接问用户** |
| **不猜** | 声库名、唱法名读不到就问用户,不要编 |

## 六、交付前自检

```
□ 我先列了**全部**轨与组吗?(不是只看当前组)
□ 我确认过索引基数吗?(1 起 vs 0 起)
□ 我查的是**这个版本**的基准歌词吗?
□ 我的改动是**一次一样**、而且用户每一步都听过吗?
□ 我有没有覆盖用户已经调好的值?
□ 唱法值加起来超过 150 了吗?
□ 破坏性操作先给 dry-run 了吗?
□ 我在宿主回调里做过 IO 吗?(绝不允许)
□ 我猜了什么本来该问用户的东西吗?
```
