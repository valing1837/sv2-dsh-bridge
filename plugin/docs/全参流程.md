# 全参流程 —— SV2 调参标准作业程序

> 用户 2026-10-02 定稿:"以后就这么搞"。
> 这份文档是**操作规范**,不是工具说明书。工具细节见 `README.md` 和 `tools/README.md`。

---

## 0. 一句话

**"全参"不是"把所有参数都用上",而是"每个参数都跟着歌曲走"。**

用户的原话:

> 全参应该是参数随歌曲进行,情感等参数随这些动态变化的,哪有一个调调唱完一首歌的。
> 声库的声线这么多,不得好好利用一下。

所以判据是:**同一首歌里,参数的值在变**(逐音符 / 逐乐句),而不是一个值唱到底。

## 1. 八步流程

| # | 步骤 | 工具 | 只读? |
|---|---|---|---|
| ① | **工程全貌** | `group_ops {action:"list"}` | ✅ |
| ② | **布局体检** | `quantize {dryRun:true}` | ✅ |
| ③ | **量化** | `quantize {dryRun:false}` | ❌ |
| ④ | **音域适配** | `auto_tone_shift {dryRun:true/false}` | 两段 |
| ⑤ | **歌词体检** | `check_lyrics {context:5}` | ✅ |
| ⑥ | **逐音符表情** | `auto_expression {dryRun:true/false}` | 两段 |
| ⑦ | **分段曲线** | `set_automation` | ❌ |
| ⑧ | **声线交叉淡化** | `set_automation {type:"vocalMode_*"}` | ❌ |

**铁律:①~⑤ 全是只读的,先出报告;⑥~⑧ 每一步都要先 dry-run 或先给方案。**

⚠️ **音高曲线不要碰**(用户 2026-10-07 试过之后定的):`pitchDelta` / `write_pit` /
手画音高线一律别动 —— 见 §2 的 ⑨ 那条。

## 2. 每一步的要点

### ① 工程全貌 —— 不能只看当前组

**踩过的坑**:letter song 有 5 条人声轨、约 10 个组、1296 个音符,
而我只看到"当前组"(317 个,占 24%)就开工了。

```
group_ops {action:"list"}
→ 每轨每组的 trackIndex / groupIndex / groupName / noteCount
```

⚠️ **索引基数陷阱**:

| 来源 | 基数 |
|---|---|
| `sv_context` | **1 起** |
| `group_ops list` | **0 起** |

**差一位 ⇒ 改到相邻的轨。每次都要确认。**

### ②③ 量化

`quantize {dryRun:true}` **顺带完成布局体检** —— 它会报"量化会造成 N 处重叠"。

**判读**:

- **没报错** ⇒ 没有重叠;若全部 `deltaQuarter: 0` ⇒ **本来就量化好了,不用做**
- **报重叠** ⇒ 说明相邻音符挨得比网格还近(连奏)⇒ **建议跳过**

**为什么常常该跳过**:转录/手打的演奏**本来就不在网格上**,硬吸会变僵。
《送别》那次三种方案分别撞 63 / 13 / 15 处 —— 那是演奏的律动,不是错误。

### ④ 音域适配

**先查声库官方音域**(`databases/meta/*.json` 的 `pitchRange`,或厂商页面)。

```
auto_tone_shift {trackIndex, groupIndex, lowPitch, highPitch, dryRun:true}
→ adjustedNotes / maxAbsCents
```

**判据**:

| `maxAbsCents` | 结论 |
|---|---|
| 0 | 不用做 |
| ≤100(1 个半音) | ✅ 补,听不出来 |
| 100~400 | ⚠️ 能补,但会有音色变化 |
| >400 | ❌ **别补** —— 那是明显变调,应该换声库或整曲移调 |

**踩过的坑**:Ayame 2 音域只有 11 个半音宽(B3–A#4),
而 letter song 的和声轨 47% 的音符超出范围、需要 600 音分补偿
—— **那不是"补多少"的问题,是方案要重选**。

⚠️ **不要自作主张把 `maxCents` 调大** —— 顶到上限说明方案本身不成立。

### ⑤ 歌词体检

```
check_lyrics {trackIndex, groupIndex, context:5}
```

**两类问题**:

1. **无效音素串**(客观错误,不需要原词)
   SV2 认不出音节时会把内部记号漏进歌词字段,形如 `.k h` `.cl m` `.ky`。
   **判据**:含 `.` 或空格。

2. **和期望序列不一致**(需要 `expected`)
   给了 `expected` 才做,逐音节比对,自动跳过 `-`。

**`context: N`** 返回每处问题前后各 N 个音符的歌词 ——
有了上下文才能**推断该填什么**(不用把全量歌词读回来)。

**常见错误类别**(成批出现,不是零散笔误):

| 类别 | 例子 |
|---|---|
| 清音/浊音 | `ta↔da` · `ka↔ga` · `to↔do` |
| 韵尾 | `-n/-ng`:`chuang→chang` · `cang→can` · `shang→shan` |
| 声母 | `chi→zhi` · `zi→ci` · `ju→qu` · `dai→lai` |
| 韵母 | `zhu→zhuo` · `yao→ya` · `jiu→jiao` |
| 认不出音节 | `.xx` → 真音节或 `-` |

⚠️ **`-` 是连音,不占音节** —— 数音节时必须跳过,否则整句错位。
⚠️ **转录的"关系"也可能错**:该是 `-` 的填了字,或一个音节被拆成两个音符。

⚠️ **基准歌词必须查证**:
《送别》朴树版和标准李叔同版有 4 处不同(一**瓢**/一**壶**、**今千里**/**情千缕**、
声声**喋喋**催/声声**离笛**催、几时**来**/几时**还**),而**转录全部按朴树版唱的**
—— 凭印象改就会改错。

⚠️ **YouTube 自动字幕不能当基准** —— 它自己就有错(`問いかけた` 被转成 `追いかけた`)。

### ⑥ 逐音符表情(这是"全参"的核心)

```
auto_expression {trackIndex, groupIndex, scale, dryRun:true}
→ stats: {min, max, mean, nonZero}
```

**按旋律走向逐音符生成**,不是分段常量:

| 参数 | 规则 |
|---|---|
| **气声** | 上行 `+` · 长音 `+` · 乐句末 `+` |
| **张力** | 下行 `+` · 大跳(≥4 半音)`+` · 乐句末 `−`(收尾要松) |
| **颤音** | 只给 ≥2 拍的长音,按长度递增;短音保持中性 `1.0` |

⚠️ **dry-run 要看分布,不是看第一个点** —— 第一个点永远是 0/0/1.0(没有前一个音可比)。
`nonZero` 最有用:它告诉你**有多少个音符真的被改动了**。

### ⑦ 分段曲线

**可用的类型**(本机实测,`get_automation` 的报错信息会列全):

```
breathiness · gender · loudness · pitchDelta · tension
toneShift · vibratoEnv · voicing · vocalMode_<名字>
```

⚠️ **文档 ≠ 本机能力**:官方文档列了 `mouthOpening`,本机**不支持**。

**按风格选,没必要的不要提**(见 §3)。

⚠️ **两套"音高"别混为一谈**(2026-10-07 用户要求"音高曲线也要用上"之后重新厘清):

| | 是什么 | 破坏性 | 什么时候用 |
|---|---|---|---|
| **`pitchDelta`**(自动化参数,**音分**) | **相对**偏移,加在音符音高**之上** | **非破坏性** —— 转录的音高 / 颤音 / 滑音全在 ✓ | 加"人味":句尾的落、大跳前的滑(见 ⑨) |
| **`PitchControlCurve`**(手画音高线,`get_pit` / `write_pit` / `clear_pit`) | **替代**音符音高 | ⚠️ 写下去转录的东西就没了 | 只在**明确要重画**时才用 |

⇒ **动手前先 `get_pit`**:
- 有曲线(`count > 0`)⇒ 那是转录的宝贝,别用 `write_pit` 覆盖它;
- 没有(`count = 0`,本工程 `太委屈` 就是这样)⇒ 音符音高本来就是宿主算出来的,
  谈不上"覆盖",用 `pitchDelta` 加微表情是安全的。

### ⑧ 声线交叉淡化

**这是"利用声线"的正确方式。**

⚠️⚠️ **唱法是互斥的,不是可叠加的图层。**

**踩过的大坑**:同时给 5 个模式高值(总和 300+)⇒ 参数互相打架 ⇒
**出来是"大烟嗓"**,用户原话:"什么鬼,怎么成大烟嗓了"。

**安全规则:任意时刻所有唱法值的总和 ≤ 150。**

```json
// 主歌   Mellow 70 · Pops 30 · Sweet 20           = 120
// 预副歌 Mellow 40 · Pops 70 · Emotional 20       = 130
// 副歌   Mellow 10 · Pops 110 · Emotional 30      = 150  ← 上限
// 尾段   Mellow 30 · Pops 90 · Sweet 30           = 150
// 收尾   Mellow 50 · Pops 50 · Soft 40            = 140
```

**一个段落里最多 3 个模式**,而且要**此消彼长**(一个上去另一个下来)。

⚠️ **模式名要靠用户"点一下"才能读全**:
`getVoice()` 只返回**显式设过**的模式,继承来的读不出来 ——
这是官方 API 的硬限制。**不猜,请用户在 SV2 的「歌声」面板动一下。**

⚠️ **换声库不会清掉旧模式** —— 残留值会一直报给你。判据:名字对不上当前声库 ⇒ 是残留。

### ⑨ 音高微表情 —— **试过,别用**

2026-10-07 做过一版 `auto_pitch`(句尾下滑 / 大跳从对侧滑入 / 句中长音下坠,写 `pitchDelta`)。
用户听完的原话:**"非常怪"** ⇒ **默认不要做音高微表情。**

op 还留着(桥 0.8.5 起有),但**流程里划掉**。要表达情感请用
**气声 / 张力 / 颤音包络(⑥)· 响度(⑦)· 唱法交叉淡化(⑧)** —— 这几层才是安全的。

⚠️ 想撤掉已经写进去的那条曲线:在 SV2 里 **Ctrl+Z 一次**(它是一整笔撤销步)。
宿主没提供"删自动化点"的 API,桥这边**没法**程序化清掉它 ⇒ **"别写"比"写了再撤"重要**。

<details>
<summary>当时那版的三条规则(留作记录,别照着做)</summary>

```
auto_pitch {trackIndex, groupIndex, scale, dryRun:true/false}
→ stat: {fall, slide, drift} · stats: {min, max, mean, nonZero} · rangeCents
```

| 情形 | 处理 |
|---|---|
| **句尾**(下一个音之前有 ≥1 拍空隙,或就是最后一个音) | 尾音**下滑** 60 音分 |
| **大跳**(与下一个音相差 ≥4 半音) | 到达前**从对侧滑入** 70 音分(往上跳就从下方来,往下跳就从上方来) |
| **句中长音**(≥2 拍且与下一个音相连) | 尾段**轻微下坠** 25 音分(声音自然会松) |

写的是 **`pitchDelta`(相对)** ⇒ 音符音高一点没动(这条性质本身没错,错的是"该不该动它")。

</details>

## 3. 按风格选参数

⚠️ **不是每个参数都要改** —— 没必要的**提都不要提**(提了是噪音)。

| | 抒情慢歌(送别 / 梦回还) | **舞曲 / J-Pop(LOVE 2000)** |
|---|---|---|
| 气声 | `+0.05 ~ +0.15`(核心质感) | **不用** —— 会糊 |
| 张力 | `−0.05 ~ −0.20`(压低,松弛) | **不用** —— 会散 |
| 响度幅度 | `−3 ~ +1 dB`(大起落) | `−2.5 ~ +0.5 dB`(**平**) |
| 唱法 | 多模式切换 | 单模式变强度,或轻量交叉淡化 |

**舞曲要的是"清晰、有劲、能量稳定"** —— 大起大落会打断律动。

## 4. 操作纪律(全是踩过的坑)

| 纪律 | 踩过的坑 |
|---|---|
| **一次只加一样,每步听** | 十几个变量一起上 ⇒ 出问题定位不了 |
| **绝不覆盖用户手工调校** | 用户已经调过 6 个唱法 + gender,我只微调不重做 |
| **和声轨不碰**(除非明确要求) | 用户:"和声不需要干呀" |
| **唱法总和 ≤150** | 300+ ⇒ "大烟嗓" |
| **索引基数要确认** | `sv_context` 1 起 vs `group_ops list` 0 起 |
| **宿主回调里不做 IO** | `io.popen` 跑 `dir` **把 SV2 冻住**了 —— 系统调用阻塞 UI 线程 |
| **写入前先读,写入后回读** | 所有写 op 都返回 `readBack` |
| **失败要 fail-closed** | 量化撞车就整批不写,不是写一半 |

### 关于 `io.popen` 那次事故

**桥的 op 是在宿主的定时器回调里执行的** —— 那里做**任何系统调用**都可能阻塞 UI 线程。
`io.popen` 跑 `dir` 列目录,`dir` 一卡,**整个 SV2 冻住**。

⇒ **纪律:宿主回调里只做纯计算和 API 调用。绝不做 IO / 进程操作。**
需要文件信息就:① `io.open` 读已知路径(打不开就如实报错);② 或者**问用户**。

**永久封锁**:所有 `io.popen` 调用点已替换成 `POPEN_BLOCKED()`(立刻报错)。

## 5. 工具速查

**5 个 op 支持 `trackIndex` / `groupIndex`**(多轨工程必需 —— 脚本切不了"当前组"):

```
auto_tone_shift · set_automation · get_automation · get_voice · set_voice
```

**不加这两个参数时行为不变**(退回当前组)。

| 想干什么 | 用什么 |
|---|---|
| 列全部轨与组 | `group_ops {action:"list"}` |
| 音域体检/适配 | `auto_tone_shift {lowPitch, highPitch, dryRun}` |
| 歌词体检 | `check_lyrics {context:5}` |
| 逐音符表情 | `auto_expression {scale, dryRun}` |
| 读写曲线 | `get/set_automation {type, points}` |
| 读写声库属性 | `get/set_voice` |
| 看宿主算出的音素 | `get_computed {kind:"phonemes"}` |
| 问用户要选择 | `panel_ask {prompt, choices}` |

## 6. 已知的工具限制

| 限制 | 说明 |
|---|---|
| **没有 `setCurrentGroup`** | 官方 API 只有 `getCurrentGroup` ⇒ 脚本切不了当前组,只能用 `groupIndex` |
| **`getVoice()` 只读显式值** | 继承来的唱法读不出来 ⇒ 请用户点一下 |
| **没有保存接口** | 26 个类全查过 ⇒ 助手**没法**替你保存工程 |
| **`get_layout` 没有 summary 模式** | 300+ 音符的组,payload 太大 ⇒ 拿不到"当前重叠数" |
| **`get_group_voice` 已停用** | 它靠 `io.popen` 读文件 ⇒ 冻宿主。声库名只能问用户 |
| **没有 `group_ops list`** | ✅ **已补**(2026-10-02) |
| **`check_lyrics` / `auto_expression`** | ✅ **已补**(2026-10-02) |
